# ELISEI 5.4.4 — единое хранилище данных WB и автоматическое восстановление

Патч исправляет ситуацию, когда раздел «Синхронизации» показывает загруженные товары, заказы, продажи, остатки и рекламу, а «Главная», «Аналитика», «Товары», «Остатки», «Финансы», «Реклама» и Эл получают пустые данные.

## Причина

Счётчики синхронизации хранились в `wb_sync_states`, а рабочие разделы читали большой общий JSON `marketplace_connections.data`. При частичной записи, фоновом повторе или обновлении одного потока общий JSON мог потерять массивы других потоков.

## Что изменено

- создана таблица `wb_stream_data` с отдельной записью для каждого потока и кабинета:
  - `products`;
  - `orders`;
  - `sales`;
  - `stocks`;
  - `advertising`;
- каждый поток сохраняется сразу после успешного ответа WB, до финального обновления статуса синхронизации;
- все рабочие API-разделы читают данные через единый канонический слой;
- уже загруженные данные автоматически восстанавливаются:
  1. из `wb_stream_data`;
  2. из старого `marketplace_connections.data`;
  3. из последних проверенных снимков `wb_api_snapshots`;
- повторно загружать 9 201 заказ, 8 280 продаж и остальные данные из WB не требуется;
- большой JSON подключения больше не хранит массивы потоков — только статусы и манифест источников;
- добавлен маршрут ручной проверки/восстановления `POST /api/wb/data-repair/:id`;
- диагностика `/api/wb/diagnostics/:id` показывает источник, количество и дату каждого потока;
- фоновые повторы и официальный отчёт остатков используют то же единое хранилище;
- данные разных пользователей и кабинетов изолированы по `connection_id`.

## Установка

Загрузить **содержимое архива** в корень репозитория ELISEI с заменой файлов.

Render backend:

```text
Root Directory: backend
Build Command: npm install
Start Command: npm start
```

Затем выполнить:

**Manual Deploy → Clear build cache & deploy**

Frontend менять и передеплоивать не требуется.

После успешного backend deploy:

1. открыть сайт ELISEI;
2. обновить страницу через `Ctrl + F5`;
3. открыть «Главная» или «Аналитика»;
4. первый запрос автоматически перенесёт старые данные в `wb_stream_data`;
5. проверить «Товары», «Остатки», «Финансы», «Реклама» и Эла.

## Проверка backend

В `/health` должна быть версия backend `2.9.0`.

Локально:

```bash
cd backend
npm test
node --check src/server.js
```

## Важно

- токен WB повторно добавлять не нужно;
- новую полную синхронизацию запускать не нужно;
- MAXADORRE не затрагивается;
- OpenAI и тарифные режимы Эла не изменяются;
- архив содержит менее 100 файлов.
