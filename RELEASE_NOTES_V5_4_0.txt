ELISEI 5.4.0 — WB Integration Core
Backend 2.8.0

Главное изменение
-----------------
Интеграция Wildberries больше не строит рабочие экраны напрямую из случайно разобранного ответа API. Добавлен отдельный проверяемый слой:

WB API → исходный JSON-снимок → строгий адаптер метода → единая карточка товара → PostgreSQL → интерфейс.

Что исправлено
--------------
1. Каталог
- Строгий разбор POST /content/v2/get/cards/list.
- Сохраняются nmID, артикул продавца, фото, размеры, chrtID и все ШК из sizes[].skus[].
- Проверяются дубли nmID.

2. Остатки
- Новый отчёт создаётся с группировками groupBySa, groupByNm, groupByBarcode и groupBySize.
- Старые незавершённые taskId без этого профиля не используются.
- Родительские nmId, vendorCode, barcode и techSize сохраняются в каждой складской строке.
- Транзитные и агрегирующие строки не суммируются повторно.
- Сопоставление: ШК размера → nmID → артикул продавца → chrtID (резервно).
- Контроль суммы: сопоставлено + не сопоставлено = общий итог отчёта.
- Положительный снимок без идентификаторов отклоняется и не попадает в рабочие экраны.

3. Реклама
- Список кампаний и статистика разделены.
- /adv/v3/fullstats запрашивается партиями до 50 кампаний.
- Статистика связывается с товаром по nmID.
- Подтверждённые нулевые значения остаются нулями.
- Кампания без ответа статистики показывает «не загружено», а не ложные нули.
- Следующая синхронизация продолжает следующую партию кампаний.

4. Единая модель товара
- Фото.
- nmID WB.
- Артикул продавца.
- Размеры и ШК.
- Остаток по товару, ШК и складам.
- Реклама и расход по nmID.
- Существующие продажи, возвраты, себестоимость, затраты и прибыль объединяются в одной строке интерфейса.

5. Диагностика и надёжность
- Исходные и нормализованные ответы ключевых методов сохраняются в wb_api_snapshots.
- Для снимков сохраняются checksum и результат проверки.
- Добавлен GET /api/wb/diagnostics/:id.
- В журнале синхронизаций показывается целостность каталога, остатков и рекламы.
- Ошибка браузера «Failed to fetch» заменена понятным сообщением о недоступности backend.

Проверки
--------
- node --check для backend и модулей: успешно.
- Автотест ядра WB: успешно.
- Синтаксический разбор 11 frontend JS/JSX-файлов: успешно.
- Полная Vite-сборка в рабочей среде не выполнена: внутренний npm-реестр не содержит lucide-react. На Render зависимость загружается обычной командой npm install.

Важно после деплоя
------------------
Снимки остатков старых схем намеренно не используются. После обновления нужен один новый этап «Остатки», чтобы WB сформировал детальный отчёт с nmID, артикулом и ШК. API-токен повторно вводить не требуется.
