# ELISEI 5.13.8 — Phone Call Verification

Hotfix поверх 5.13.7 после фактического ответа SMS.RU `221`: обычная отправка SMS требует зарегистрированного буквенного отправителя. Для кодов регистрации и восстановления это лишняя зависимость, поэтому ELISEI переводит подтверждение телефона на официальный SMS.RU `code/call`.

## Что изменено

- При регистрации ELISEI запрашивает входящий проверочный звонок вместо SMS.
- Пользователь не отвечает на звонок, а вводит последние 4 цифры номера, с которого поступил вызов.
- Код хранится только как HMAC; сам 4-значный код в базе ELISEI не сохраняется.
- В SMS.RU передаётся IP пользователя для встроенной защиты от злоупотреблений.
- Сохраняются прежние ограничения ELISEI: повтор не чаще раза в минуту, максимум 5 проверок в час на номер, код действует 5 минут, максимум 5 попыток.
- Восстановление пароля использует тот же звонок.
- Для legacy-аккаунта, созданного до обязательного телефона, восстановление принимает прежний email и `OWNER_RECOVERY_PHONE`; после успешного сброса номер записывается в старый аккаунт, а данные пользователя не дублируются.
- Смена телефона в авторизованном аккаунте на backend также переведена на `code/call`.
- Старые auth URL сохранены ради обратной совместимости с уже развёрнутыми клиентами; транспорт внутри них больше не SMS.
- `/health` сообщает `mode=phone_call_code`, provider `sms.ru/code/call`.

## Версии

- Frontend: `5.13.8`
- Backend: `2.25.8`
- El Core: без изменения бизнес-логики аналитики

## Проверка после деплоя

1. `/health` показывает backend `2.25.8` и `authRecovery.mode=phone_call_code`.
2. На регистрации кнопка называется «Получить звонок», поле принимает 4 цифры.
3. На восстановлении запрашиваются email и телефон, после звонка вводятся последние 4 цифры входящего номера.
4. Старый аккаунт без телефона восстанавливается через legacy owner bridge и получает телефон только после правильного кода.
5. Буквенный отправитель SMS.RU для этого сценария не требуется.
