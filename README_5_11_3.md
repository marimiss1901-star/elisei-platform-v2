# ELISEI 5.11.3 — SKU 360 Fast Open

Hotfix для живого кабинета, где SKU 360 мог бесконечно оставаться на skeleton «Собираю SKU 360».

## Что исправлено

1. SKU 360 теперь открывается в два этапа:
   - `depth=core` — быстрый ответ из уже собранного ядра и компактных сохранённых выборок;
   - `depth=full` — фоновое обогащение отзывами, поиском, историей остатков и финансовыми движениями.
2. Тяжёлое обогащение больше не блокирует первую отрисовку карточки.
3. Основной запрос SKU 360 больше не зависит от технических изменений Smart WB Scheduler (`status`, `nextAllowedAt`), поэтому фоновые изменения очереди не отменяют уже запущенный запрос каждые 15 секунд.
4. Автообновление SKU 360 реагирует только на реальные изменения данных: `lastSuccessAt`, количество сохранённых строк/товаров и фактические результаты синхронизации.
5. Тяжёлый поиск расширенных строк больше не делает до пяти `payload::text ILIKE + COUNT(*)` проходов на один поток. Используется один точный проход по подтверждённым идентификаторам SKU, после чего строки повторно проверяются строгим `product360Matches`.
6. Для core-выборки sample/truncated данные всегда считаются `partial` и не могут доказать нулевой показатель по SKU.
7. Запросы SKU 360 получили ограниченное время ожидания: core 12 секунд, full 25 секунд. Если full не успевает, уже открытая карточка остаётся доступной.

## Версии

- Frontend: 5.11.3
- Backend: 2.23.3
- El Core: 5.11.3

## Проверка после деплоя

1. `/health` → backend `2.23.3`.
2. Открыть любой товар.
3. Skeleton должен быстро смениться основным SKU 360.
4. Если расширенные данные ещё собираются, появится нейтральная плашка «Основные данные готовы» вместо вечного skeleton.
5. Оставить карточку открытой во время фоновой синхронизации — технические изменения scheduler не должны возвращать её в состояние бесконечной загрузки.
