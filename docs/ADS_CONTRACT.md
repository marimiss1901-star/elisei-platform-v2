# ELISEI — контракт рекламного центра WB 5.3.13

## Единый токен

Рекламный модуль не использует отдельный `WB_PROMOTION_TOKEN`. Все WB-разделы получают единый токен выбранного кабинета.

Для текущего одного кабинета допускается серверная переменная:

```env
WB_API_TOKEN=...
ELISEI_TOKEN_MODE=environment
WB_DEFAULT_CABINET_ID=maria-wb-main
```

Для коммерческой версии:

```env
ELISEI_TOKEN_MODE=database
```

Токен пользователя хранится в базе только в зашифрованном виде и расшифровывается на backend непосредственно перед запросом к WB.

## Серверный резолвер

Елисей ожидает функцию:

```js
app.locals.resolveWbCabinetToken = async ({
  userId,
  cabinetId,
  marketplace,
  permission,
  req,
}) => ({
  token,
  userId,
  cabinetId,
  cabinetName,
});
```

Требования:

- пользователь должен быть определён серверной авторизацией (`req.user`, `req.auth` или сессия);
- поиск кабинета выполняется одновременно по владельцу и ID кабинета;
- токен не возвращается клиенту и не записывается в логи;
- frontend передаёт только `X-ELISEI-CABINET-ID`;
- заголовок не считается доказательством владения: владение проверяет резолвер.

## Разделение данных

Кэш рекламы имеет отдельный криптографический scope для каждой комбинации:

```text
пользователь + кабинет + отпечаток токена
```

Поэтому одинаковый период двух продавцов сохраняется раздельно.

## Ошибки доступа

- `WB_CABINET_TOKEN_MISSING` — кабинет не подключён или токен не найден;
- `WB_CABINET_FORBIDDEN` — кабинет не принадлежит пользователю;
- `WB_TOKEN_INVALID` — WB отклонил токен;
- `WB_PROMOTION_ACCESS_DENIED` — у единого токена нет категории «Продвижение»;
- `WB_RATE_LIMIT` — сработал лимит запросов WB.

## Источник рекламы

Модуль использует только методы чтения WB Promotion API:

- `GET /adv/v1/promotion/count`;
- `GET /adv/v3/fullstats`;
- `GET /api/advert/v1/config`.

Операции запуска, остановки, изменения ставок и пополнения бюджета не выполняются.

## Период

Каждый endpoint принимает глобальный период Елисея:

```text
date_from=2026-07-01
date_to=2026-07-30
compare=1
compare_from=2026-06-01
compare_to=2026-06-30
```

Диапазоны длиннее 31 дня автоматически делятся на части. Кампании запрашиваются пакетами до 100 ID.

## Endpoint

- `GET /api/ads/health`
- `GET /api/ads/overview`
- `GET /api/ads/campaigns`
- `GET /api/ads/products`
- `GET /api/ads/el-insights`
- `POST /api/ads/sync`

## Прибыль после рекламы

Рекламная статистика связывается с товаром по `nmID`. Артикул продавца, фото, остаток, себестоимость, комиссия и логистика берутся из единой карточки товара.

```text
Прибыль после рекламы = рекламная выручка
                      - себестоимость проданных единиц
                      - комиссия маркетплейса
                      - логистика
                      - рекламный расход
```
