# Матрица доступов Wildberries для ELISEI

## Основное правило

ELISEI предпочитает один универсальный токен магазина. Если этот токен содержит все нужные категории, он обслуживает все потоки и дополнительные ключи не требуются.

Дополнительный токен используется только для категории, которой нет в основном ключе. Запросы через разные токены не дублируются.

| Поток | Категория WB | Текущий статус |
|---|---|---|
| Карточки и фото | Контент | Реализовано |
| Заказы | Статистика | Реализовано |
| Продажи и возвраты | Статистика | Реализовано |
| Остатки WB | Аналитика | Реализовано через асинхронный отчёт |
| Рекламные кампании | Продвижение | Реализовано |
| Отзывы и вопросы | Вопросы и отзывы | Следующий этап |
| Финансовые отчёты | Финансы | Следующий этап |
| Чаты | Чат с покупателями | Следующий этап |
| Управление ценами | Цены и скидки | Следующий этап, только с явным подтверждением пользователя |

## Выбор токена

1. Токен с наибольшим покрытием рабочих потоков автоматически назначается основным.
2. Для каждого запроса сначала проверяется основной токен.
3. Дополнительный ключ выбирается только если основной не содержит нужной категории.
4. Пользователь может вручную назначить основной токен.
5. При удалении основного ключа ELISEI автоматически выбирает наиболее полный из оставшихся.

## Безопасность

- Не смешивать токены разных кабинетов продавца.
- Не возвращать сохранённый токен во frontend.
- Не заменять успешный срез пустыми данными при 429/5xx.
- Показатели без успешной загрузки отображать как «Не загружено».
- ELISEI — облачный SaaS: Персональные токены не принимаются. До регистрации сервиса используется Базовый токен со сниженными лимитами.
- После регистрации сервиса используется Базовый токен с `WB_CLIENT_SECRET`, а после публикации в Каталоге решений — Сервисный токен или OAuth 2.0.
