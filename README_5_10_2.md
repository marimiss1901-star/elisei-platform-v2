# ELISEI 5.10.2 — быстрые финансы и честная оцифровка

## Что исправлено

### 1. Финансовая пагинация WB

В 5.10.1 в `backend/src/wb/finance-core.js` оставалось старое ограничение для базового токена: следующая страница финансовой детализации назначалась через 12 часов.

В 5.10.2:

- `sales-reports/detailed` продолжается примерно через 21 секунду;
- уже сохранённая 12-часовая пауза автоматически сбрасывается при открытии кабинета или запуске фонового worker;
- курсор `rrdId`, уже сохранённые строки и прогресс не теряются;
- реальный `429` от WB не переписывается миграцией — для него по-прежнему используется серверный `X-Ratelimit-Retry`.

### 2. Retry по заголовкам WB

Если WB отвечает `429`, `X-Ratelimit-Retry` считается точным интервалом. Раньше ELISEI применял к нему jitter и мог повторить запрос раньше разрешённого времени. Теперь к явному Retry-After добавляется только небольшой защитный запас.

### 3. Главная больше не показывает ложные нули

На «Оцифровке кабинета» метрики учитывают доступность потока за выбранный период.

Пока данные не подтверждены:

- выручка/заказы/продажи/возвраты → «Догружается» или «Не загружено»;
- комиссия, логистика, хранение, эквайринг, штрафы → не показываются как `0 ₽` только потому, что финансовый поток ещё не закончен;
- «К перечислению» может показывать предварительное значение только если в финансовом реестре уже есть движения выбранного периода;
- операционная прибыль без себестоимости показывает «Не рассчитано»;
- топ товаров по выручке не строится до появления продаж.

### 4. Rate limit теперь объясняется правильно

В журнале синхронизаций вместо общего «Пауза Wildberries» показывается «Лимит метода WB» и прямо указано, что ждёт только конкретный поток, а остальные продолжаются независимо.

## Проверка

После деплоя:

1. `/health` должен вернуть backend `2.22.2`.
2. Открыть «Синхронизации» — старая финансовая пауза до вечера должна исчезнуть и перейти в ближайшую очередь.
3. Финансы должны добавлять страницы примерно раз в 20–21 секунду, пока WB не вернёт завершение или собственный `429`.
4. Главная не должна показывать `0 ₽` как подтверждённый факт для ещё не загруженных расходов.
