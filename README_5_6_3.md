# ELISEI 5.6.3 — совместимость WB API: архив FBS, meta/details и СГТ-склады

Прямое обновление поверх **ELISEI 5.6.2**. Релиз не меняет данные MAXADORRE и не добавляет управление складами продавца.

## Архив FBS

Поток «Архив FBS» проверен и переведён на отдельный строгий контракт:

- официальный метод `GET /api/marketplace/v3/fbs/orders/archive`;
- выборка помесячно для заданий старше трёх месяцев;
- `limit=1000` и полное продолжение по курсору `next`;
- пустая страница с новым курсором не считается концом архива;
- защита от зациклившегося курсора;
- стабильный ключ задания, поэтому повтор страницы не создаёт дубль;
- фиксированный план месяцев сохраняется в PostgreSQL и не сдвигается после перезапуска;
- незавершённая очередь из 5.6.2 продолжает тот же месяц после обновления;
- в карточке синхронизации видны текущий месяц, страница, сохранённые задания и итоговое покрытие;
- после завершения показывается подтверждённое число строк и количество проверенных месяцев.

По умолчанию проверяются 24 месяца. Значение можно изменить переменной `WB_FBS_ARCHIVE_MONTHS` от 1 до 60.

## Актуальные методы метаданных

Создан единый защитный слой WB API. Устаревшие методы блокируются до выполнения сетевого запроса:

- DBS: `POST /api/marketplace/v3/dbs/orders/meta/info` → `POST /api/marketplace/v3/dbs/orders/meta/details`;
- DBW: `GET /api/v3/dbw/orders/{orderId}/meta` → `POST /api/marketplace/v3/dbw/orders/meta/details`;
- Самовывоз: `POST /api/marketplace/v3/click-collect/orders/meta/info` → `POST /api/marketplace/v3/click-collect/orders/meta/details`.

Для новых интеграций добавлен общий построитель запросов `buildOrderMetaDetailsRequest()`. Старый адрес нельзя случайно вернуть в код без падения тестов.

## СГТ-склады после 5 августа 2026 года

ELISEI работает с СГТ-складами в режиме **только чтение**:

- `GET /api/v3/warehouses` продолжает загружать уже созданные склады продавца, включая `cargoType: 2`;
- остатки таких складов читаются через текущий поток FBS;
- СГТ-склады не отбрасываются из-за отсутствия в `GET /api/v3/offices`;
- создание и редактирование `cargoType: 2` блокируется внутри клиента до отправки запроса;
- после даты ограничения любое изменение склада без явно известного типа груза также блокируется;
- в интерфейсе указано, что управление СГТ выполняется только в личном кабинете Wildberries.

Обычные склады типов `cargoType: 1` и `cargoType: 3` защитный слой не запрещает, но ELISEI 5.6.3 сам не добавляет экранов управления складами.

## Диагностика

Маршрут backend `/health` показывает активную политику:

- актуальный endpoint архива FBS;
- endpoints `meta/details` для DBS, DBW и Самовывоза;
- дату прекращения API-управления СГТ;
- режим `seller-cabinet-only`.

## Установка

Скопируйте содержимое патча в корень репозитория с заменой файлов.

1. Backend Render: **Manual Deploy → Clear build cache & deploy**.
2. После статуса Live — frontend Render: **Clear build cache & deploy**.
3. Обновите кабинет через `Ctrl + F5`.
4. В «Синхронизациях» отдельно запустите «Архив FBS» или дождитесь продолжения фоновой очереди.
