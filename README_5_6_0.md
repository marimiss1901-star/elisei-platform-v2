# ELISEI 5.6.0 — полный финансовый контур WB

Прямое обновление поверх **ELISEI 5.5.0**. MAXADORRE и его данные не затрагиваются.

## Что добавлено

### Официальные сводки финансовых отчётов

- список отчётов реализации через `/api/finance/v1/sales-reports/list`;
- список отчётов эквайринга через `/api/finance/v1/acquiring/list`;
- постраничное сохранение в PostgreSQL с продолжением после лимитов WB;
- контроль периода, ID отчёта, розничной суммы, суммы к перечислению, логистики, хранения, приёмки, штрафов, удержаний, банковской выплаты, комиссии эквайринга и НДС;
- отдельный статус, когда тип токена не поддерживает новые финансовые методы.

Сводки используются для сверки. Они не подмешиваются в P&L повторно и не заменяют детализацию операций.

### Полная расшифровка удержаний

- фактические замеры склада через `/api/analytics/v1/warehouse-measurements`;
- удержания за самовыкупы через `/api/v1/analytics/antifraud-details`;
- штрафы за отсутствие или нечитаемую маркировку через `/api/v1/analytics/goods-labeling`;
- сохранение фотофиксации, размеров, объёма, периода и суммы;
- существующие отчёты по заниженным габаритам, подменам и неверным вложениям объединены в один блок причин.

Все специальные отчёты помечены как детализация. Если удержание уже входит в финансовый отчёт, оно не вычитается второй раз.

### Новые финансовые экраны

- **Отчёты WB** — сводки реализации и эквайринга;
- **Динамика** — движение денег по дням: к перечислению, расходы и удержания;
- **Причины удержаний** — габариты, замеры, подмены, самовыкупы и маркировка;
- неподтверждённый пустой поток отображается как `Ожидает WB`, а не как ноль;
- покрытие всех источников видно в синхронизациях и сверке.

## Архитектура

Количество контролируемых потоков WB увеличено с **22 до 27**:

`financeReports`, `acquiringReports`, `warehouseMeasurements`, `antifraudRetention`, `labelingRetention` добавлены в общую очередь, PostgreSQL-хранилище, диагностику и статусы токенов.

Финансовая детализация остаётся источником бухгалтерского факта для P&L. Сводки дают контроль итогов, а специальные отчёты объясняют причины штрафов и удержаний.

## Важное ограничение токена

Методы списков отчётов реализации и эквайринга WB доступны только Персональному или Сервисному токену. Облачный ELISEI использует Сервисный токен вместе с `WB_CLIENT_SECRET`. При неподходящем типе токена система показывает понятную ошибку и сохраняет ранее загруженные данные.

## Установка

Архив является патчем поверх версии 5.5.0. Скопируйте его содержимое в корень репозитория с заменой файлов.

Backend Render:

- Root Directory: `backend`
- Build Command: `npm install`
- Start Command: `npm start`

Frontend Render:

- Root Directory: пусто
- Build Command: `npm install && npm run build`
- Publish Directory: `dist`

Сначала выполните **Clear build cache & deploy** для backend, затем для frontend. После деплоя откройте «Синхронизации» и запустите новые финансовые потоки.
