# ELISEI 5.4.5 — WB Data Self-Healing

Исправляет состояние, при котором журнал синхронизаций показывает загруженные строки, но Главная, Аналитика, Товары, Остатки, Финансы, Реклама и Эл получают пустые данные.

## Что изменено

1. Восстановление из `wb_api_snapshots` стало строгим и понимает реальные формы ответов WB:
   - страницы каталога `cards`;
   - массивы заказов и продаж;
   - сырой отчёт остатков;
   - кампании и статистику рекламы.
2. Чтение аналитики больше не удаляет старые данные из `marketplace_connections.data`, пока перенос в `wb_stream_data` не подтверждён.
3. Если в `wb_sync_states.last_count` есть число строк, а сам payload не найден ни в старом JSON, ни в снимке, ELISEI автоматически ставит только отсутствующий поток в очередь повторной синхронизации.
4. Повторная синхронизация выполняется существующим фоновым worker последовательно и сохраняет данные сразу в каноническое хранилище.
5. Ответы dashboard/core содержат служебное поле `recoveryQueued`, чтобы видеть, какие потоки были поставлены на восстановление.

## Установка

Загрузить содержимое архива в корень репозитория с заменой файлов.

Render backend:

- Root Directory: `backend`
- Build Command: `npm install`
- Start Command: `npm start`

После загрузки выполнить:

`Manual Deploy → Clear build cache & deploy`

Frontend обновлять не требуется.

## После деплоя

1. Открыть Главную или Аналитику. Первый запрос проверит все потоки.
2. Если снимки сохранены, показатели появятся сразу после обновления страницы.
3. Если в базе остались только счётчики, ELISEI автоматически поставит товары, заказы, продажи, остатки и рекламу в очередь. Подождать 1–3 минуты и обновить страницу `Ctrl+F5`.
4. Остатки могут восстанавливаться дольше, потому что WB формирует отдельный отчёт.

Важно: если в Render снова появляется `ECONNREFUSED ...:5432`, это отдельная проблема доступности PostgreSQL; код восстановления не может работать, пока база недоступна.
