# ELISEI

## ELISEI 5.3.7

Исправлено сопоставление остатков Wildberries с артикулами после перехода WB на идентификатор размера `chrtID`. Каталог теперь хранит размеры и их идентификаторы, отчёт остатков сохраняет `chrtId`, а аналитическое ядро суммирует все размеры и склады на карточку товара. Backend: 2.7.5.

После деплоя старого снимка нажмите в разделе «Остатки» кнопку **«Обновить товары и остатки»** один раз: сначала обновится каталог с `chrtID`, затем сформируется новый отчёт остатков.


## ELISEI 5.3.6

Исправлена целостность снимка остатков WB: общая сумма и строки детализации сохраняются и проверяются отдельно. При повреждённом старом снимке система показывает подтверждённую общую сумму, не выставляет товарам ложный нулевой остаток и предлагает один раз восстановить детализацию. Backend: 2.7.4.

# ELISEI 5.3.1

AI Operating System для аналитики и управления магазином на маркетплейсе. Текущий релиз использует один универсальный токен Wildberries как основной и поддерживает дополнительные ключи только для недостающих категорий. ELISEI и MAXADORRE по-прежнему полностью разделены ELISEI и MAXADORRE.

## Маршруты
- `/` — лендинг
- `/login` — вход
- `/register` — регистрация
- `/app` — кабинет

## Frontend / Render Static Site
- Build command: `npm install && npm run build`
- Publish directory: `dist`
- Rewrite: `/*` → `/index.html`
- Environment: `VITE_API_BASE_URL=https://<backend>.onrender.com`

## Backend / Render Web Service
- Root directory: `backend`
- Build command: `npm install`
- Start command: `npm start`

Обязательные переменные:
- `DATABASE_URL`
- `JWT_SECRET`
- `ENCRYPTION_KEY` — рекомендуется отдельная длинная случайная строка
- `FRONTEND_ORIGIN=https://<frontend>.onrender.com`
- `NODE_ENV=production`

Для текущего облачного ELISEI без регистрации у WB используется Базовый токен со сниженными лимитами. Персональные токены не принимаются, поскольку они предназначены для локальных программ продавца. `WB_CLIENT_SECRET` добавляется после регистрации сервиса; после публикации в Каталоге решений применяется Сервисный токен или OAuth 2.0.

## ELISEI 5.3.1
- один универсальный WB-токен может обслуживать все потоки;
- наиболее полный ключ автоматически назначается основным;
- дополнительные токены используются только для недостающих категорий;
- категории токенов определяются автоматически;
- товары, заказы, продажи, остатки и реклама синхронизируются независимо;
- лимиты WB сохраняются в PostgreSQL, повтор выполняется фоновым работником;
- отчёт остатков не удерживает браузер в ожидании;
- остатки доступны по складам и размерам;
- реклама загружается из WB Promotion API;
- старые успешные данные сохраняются при 429;
- отсутствующие данные показываются как «Не загружено».

## Деплой
1. Backend: `Clear build cache & deploy`.
2. Проверить `/health`: версия `2.7.1`, database `ok`.
3. Frontend: `Clear build cache & deploy`.
4. Обновить страницу `Ctrl + F5`.
5. В разделе «Подключения» проверить, что универсальный ключ отмечен как «Основной» и показывает покрытие 5/5 потоков.
6. Остальные токены можно оставить резервными или удалить, если они не дают дополнительных категорий.
7. В «Синхронизациях» запустить доступные этапы один раз. Отложенные этапы продолжатся автоматически.
