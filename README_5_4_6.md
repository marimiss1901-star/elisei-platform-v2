# ELISEI 5.4.6 — WB Full Finance + FBS/FBO

Прямой патч для текущего проекта ELISEI 5.4.5A. Установщики `apply-*.mjs` не используются: файлы из архива накладываются на корень репозитория с заменой.

## Что добавлено

### Финансовые потоки WB

Один токен выбранного кабинета используется для всех разрешённых ему методов. В синхронизацию добавлены:

- детализация отчётов реализации WB;
- фактическая комиссия WB;
- логистика и возмещение логистических/складских операций;
- платное хранение;
- платная приёмка;
- эквайринг;
- штрафы;
- удержания;
- корректировки и доплаты;
- сумма к перечислению продавцу и баланс кабинета.

Финансовые данные сохраняются отдельными потоками в PostgreSQL и не смешиваются между пользователями и кабинетами.

### FBS и FBO

- FBO-остатки загружаются из отчёта по складам WB.
- FBS-остатки загружаются отдельно по складам продавца и `chrtId`.
- Режим операции определяется по `deliveryMethod`, `warehouseType`, `srid` и признакам сборочного задания.
- В карточке товара отображается `FBS`, `FBO` или `FBS + FBO`.
- Выручка, заказы, продажи, возвраты, остатки, комиссия, логистика и прибыль считаются раздельно по схемам и затем объединяются без двойного счёта.

### Защита от двойного счёта

- Если хранение/приёмка/эквайринг уже есть в финансовой детализации, отдельный детальный отчёт не прибавляется повторно.
- Если соответствующее поле в финансовой детализации отсутствует, используется отдельный отчёт по товарам.
- Комиссия берётся как фактическое вознаграждение WB `vw + vwNds`; `ppvzSalesCommission` используется только как fallback для старого или неполного ответа.
- Ручные настройки комиссии, логистики и хранения остаются только резервом, пока API-поток не загружен.

## Развёртывание

### Backend Render

```text
Root Directory: backend
Build Command: npm install
Start Command: npm start
```

### Frontend Render

```text
Root Directory: пусто
Build Command: npm install && npm run build
Publish Directory: dist
```

Новые переменные окружения не нужны. Используется уже подключённый токен кабинета WB.

После загрузки файлов:

1. Выполните `Clear build cache & deploy` для backend.
2. После успешного запуска выполните deploy frontend.
3. В ELISEI откройте «Синхронизации» и нажмите «Запустить доступные этапы».
4. Отчёты хранения и приёмки формируются WB асинхронно. Остальные интервалы ELISEI продолжит загружать фоновой очередью.

## Что появится в интерфейсе

- 10 независимых потоков синхронизации;
- отдельные остатки FBO и FBS;
- фактические расходы WB в разделе «Финансы»;
- схема работы в таблице и карточке товара;
- экономика FBS/FBO по товару;
- экспорт P&L с комиссией, логистикой, хранением, приёмкой, эквайрингом, штрафами и удержаниями.
