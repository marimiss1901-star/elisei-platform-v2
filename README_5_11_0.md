# ELISEI 5.11.0 — SKU 360

SKU 360 превращает товар в единый объект аналитики. Пользователь больше не должен вручную собирать одну карточку из разделов «Продажи», «Финансы», «Реклама», «Остатки», «Поисковые запросы» и «Коммуникации».

## Что появилось

1. **Контекстный SKU 360.** Открывается по клику на товар из каталога, аналитики, остатков, финансов по товарам и цен/акций. Отдельного пункта в левом меню нет.
2. **Единый экран товара.** В одном drawer показываются:
   - фото, бренд, nmID, артикул продавца и схема исполнения;
   - выручка, продажи, заказы, возвраты, возвратность;
   - операционная прибыль, маржа и расходы WB;
   - рекламные кампании, расход, CTR, CPC и ДРР;
   - поисковые запросы, позиции, заказы и выручка по запросам;
   - рейтинг, отзывы 1–3 звезды, отзывы/вопросы без ответа и тексты жалоб;
   - FBS/FBO остатки, размеры/штрихкоды, склады и история остатка;
   - средняя цена, цена в ноль, целевая и пиковая цена;
   - последние движения из финансового реестра;
   - один приоритетный сигнал «Что делать первым».
3. **Покрытие данных.** SKU 360 показывает, какие потоки реально подтверждены. Отсутствующие данные не превращаются в ложные нули.
4. **Период.** Экономика и динамика пересчитываются в едином выбранном периоде ELISEI. Если поисковый снимок относится к другому периоду, это помечается отдельно.

## Защита от смешивания SKU

Сопоставление данных выполняется строго в порядке:

`nmID → barcode → vendorCode → chrtID`

Название товара **никогда не используется как ключ**. Две карточки с одинаковым названием не должны объединять продажи, отзывы, рекламу, остатки или финансовые операции друг друга.

## Backend

Добавлен endpoint:

`GET /api/wb/product-360/:connectionId?productKey=...&from=YYYY-MM-DD&to=YYYY-MM-DD`

Расширенные потоки сначала ищутся в `wb_stream_items`, после чего каждая строка повторно проходит строгую проверку идентификатора. Компактный `wb_stream_data` используется только как безопасный fallback.

## После установки

1. Заменить файлы патча поверх ELISEI 5.10.5.
2. Передеплоить backend и frontend.
3. `/health` должен показать backend `2.23.0`.
4. Открыть любой товар из раздела «Товары» — справа должен появиться SKU 360.
5. Проверить один товар с отзывами/возвратами и один товар с рекламой/поисковыми запросами.

## Проверка

Полная backend regression suite: 30/30 сценариев прошли, включая отдельный тест двух SKU с одинаковым названием.
