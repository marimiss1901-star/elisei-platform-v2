# ELISEI 5.13.4 — Daily Ready Recovery Adoption

Hotfix поверх 5.13.3.

Причина зависания закрытия 18.08 найдена в пересечении Daily Ready и обычного live polling. Если orders/sales уже находились в `rate_limited`, `queued` или `retry_scheduled` после обычного `live_poll`, Daily Ready видел незакрытый вчерашний день, но не мог переочередить поток из-за защитного blocked-статуса. После окончания паузы такой поток выполнял обычный incremental sync от последней свежей строки и не возвращался за пропущенной датой.

5.13.4 не сбрасывает реальный `next_allowed_at` WB. Вместо этого существующий ожидающий поток безопасно «усыновляется» Daily Ready: в его metadata добавляются `trigger=daily_ready_recovery`, `dailyReadyDate`, `dateFrom` и признак закрытого дня. Когда разрешённое окно наступает, тот же сохранённый поток идёт за пропущенным днём, а не за очередной свежей дельтой.

Дополнительно исправлено доказательство покрытия одного дня: min/max диапазон больше не считается доказательством наличия orders/sales внутри даты. Для закрытого дня нужны реальные `selectedRows > 0` либо явное подтверждение успешного recovery-запроса, включая подтверждённый ноль.

Регрессионная suite очищена от устаревших проверок номера текущего релиза внутри исторических feature-тестов. Полный backend regression: 42/42 команд прошли на восстановленном проекте 5.9.2 → 5.13.4. `node --check` и JSX parse также прошли.

Версии: frontend 5.13.4, backend 2.25.4, El Core 5.13.4.
