# ELISEI 5.11.1 — SKU 360 data confidence

Версии: frontend 5.11.1, backend 2.23.1, El Core 5.11.1.

Этот hotfix исправляет поведение SKU 360 на живом кабинете, когда часть потоков ещё синхронизируется.

## Что исправлено

1. Пока endpoint SKU 360 не ответил, интерфейс показывает загрузочный каркас, а не нули из общей карточки товара.
2. Для потоков введены состояния `ready`, `partial`, `waiting`, `missing`.
3. Частичный ноль не трактуется как факт. Например, `0 ₽` комиссии из незавершённого финансового реестра показывается как «Не загружено».
4. Ненулевые значения из частичного потока сохраняются как предварительные.
5. FBS и FBO оцениваются отдельно: подтверждённый ноль FBS можно показать, но ожидающий FBO не превращается в 0.
6. Отзывы, вопросы и поисковые запросы не становятся «0», пока соответствующий поток ожидает синхронизацию.
7. «Критичных сигналов не найдено» выводится только при достаточном покрытии. При неполных данных Эл сообщает, что SKU ещё собирается.
8. Открытый SKU 360 автоматически перечитывается после завершения фоновых WB-потоков.

## Проверка после деплоя

- `/health` → backend `2.23.1`.
- Открыть товар, пока продажи/финансы ещё ожидают WB.
- Во время первоначальной загрузки должны быть skeleton-карточки, а не `0 ₽` и `0%`.
- После ответа endpoint появится строка покрытия SKU с состояниями потоков.
- Частичный финансовый поток не должен выдавать ложные нули.
