# ELISEI 5.4.8A — WB async report/taskId fix

Исправляет повторное ожидание отчётов «Платное хранение» и «Платная приёмка».

## Что изменено

- `taskId` отчёта сохраняется и после перезапуска используется тот же отчёт: создать → проверить статус → скачать.
- При статусах `new`/`processing` выполняется короткий polling с backoff 7–30 секунд.
- При `429` сохраняется `taskId` и соблюдается `X-Ratelimit-Retry`; новый отчёт не создаётся.
- При `404`, `purged` или `canceled` старый `taskId` сбрасывается и задача создаётся заново.
- Отчёты с уже созданным `taskId` имеют приоритет в фоновой очереди, чтобы успеть скачать готовый файл в двухчасовое окно WB.
- Платное хранение запрашивается максимальными разрешёнными интервалами по 8 дней: 4 задания вместо 15 за 30 дней.
- Платная приёмка запрашивается одним интервалом до 31 дня: 1 задание вместо 5.
- Интерфейс отличает «отчёт уже создан и ждём готовности» от новой попытки запуска.
- Эквайринг не показывает подтверждённый ноль, пока финансовая детализация WB не завершена.

## Установка

Обновить backend и frontend с заменой файлов.

Backend Render:
- Root Directory: `backend`
- Build Command: `npm install`
- Start Command: `npm start`

Frontend Render:
- Root Directory: пусто
- Build Command: `npm install && npm run build`
- Publish Directory: `dist`

Сначала выполнить Clear build cache & deploy для backend, затем для frontend.
