# ELISEI 5.11.2 — SKU 360: единый язык состояний данных

Версии: frontend 5.11.2, backend 2.23.2, El Core 5.11.2.

Этот hotfix продолжает 5.11.1 и исправляет противоречивые подписи в SKU 360 на частично синхронизированном кабинете.

## Что изменено

1. `ready / partial / waiting / missing` теперь одинаково трактуются во всех KPI и секциях SKU 360.
2. При `partial` и отсутствии значения показывается «Пока нет в загруженной части», а не «Не загружено».
3. При `waiting` показывается «Ожидается».
4. Если поток `ready`, подтверждённый `0` остаётся настоящим нулём. Пустой ready-блок подписывается как подтверждённое отсутствие строк в выборке.
5. Верхний индикатор теперь пишет количество внутренних потоков, чтобы оно не воспринималось как число шести визуальных групп.
6. Экономические метрики получают отдельные `metricStates`, потому что хранение/приёмка/эквайринг могут быть подтверждены независимо от основной финансовой детализации.
7. Для частичного остатка UI отдельно показывает состояние FBS и FBO.
8. Пустые блоки рекламы, поиска, отзывов, остатков и финансов объясняют, является ли отсутствие подтверждённым, частичным или ожидающим.

## Проверка

- `/health` → backend `2.23.2`.
- Открыть SKU 360 на кабинете с частичными финансами и FBO в ожидании.
- В KPI не должно быть generic «Не загружено» при `partial`; должно быть «Пока нет в загруженной части» или осмысленная краткая подпись.
- Подтверждённая реклама `0 ₽` остаётся `0 ₽`.
- Остаток при FBS ready + FBO waiting не превращается в общий `0` и поясняет оба режима.
