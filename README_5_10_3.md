# ELISEI 5.10.3 — hotfix сохранённой финансовой паузы

## Что исправлено

После установки 5.10.2 у кабинета, который уже успел получить длинный финансовый `nextAllowedAt`, пауза могла сохраниться до вечера. Причина: миграция 5.10.2 искала текстовую отметку старого лимита в `metadata`, а исторические состояния не гарантировали наличие этой строки на верхнем уровне.

В 5.10.3 восстановление больше не зависит от текста. Если одновременно выполняются условия:

- stage = `finance`;
- status = `queued`;
- уже сохранены строки (`last_count > 0`);
- поток не помечен завершённым;
- `next_allowed_at` дальше чем через 2 минуты;

ELISEI считает это старым ошибочным продолжением пагинации и переносит запуск на `NOW()`.

Настоящий ответ WB `429` не затрагивается, потому что он хранится со статусом `rate_limited`, а не `queued`.

## Важно

- Курсор `rrdId` не сбрасывается.
- `syncId` не сбрасывается.
- Уже загруженные финансовые строки не удаляются.
- WB API-ключ повторно вводить не нужно.
- Миграция запускается уже во время старта backend, поэтому открывать «Подключения» для её активации больше не требуется.

## Версии

- Frontend: `5.10.3`
- Backend: `2.22.3`
- El Core: `5.10.3`

## Проверка после деплоя

1. `/health` возвращает `2.22.3`.
2. Карточка «Финансы WB» больше не должна показывать старое время до вечера.
3. После короткого continuation счётчик финансов должен продолжить расти с уже сохранённого значения.
4. Если WB реально вернёт `429`, карточка может показать «Лимит метода WB» с серверным временем Retry-After — это нормальный отдельный сценарий.
