# ELISEI 5.6.4 — сервисный токен и устойчивые фоновые повторы WB

Прямое обновление поверх **ELISEI 5.6.3**. Релиз разделяет обычное подключение кабинета и сервисный финансовый доступ, а также делает очередь устойчивой к временным ошибкам Wildberries.

## Раздельные токены

В разделе «Подключения» появились два независимых контура:

- **Базовый токен кабинета** — товары, заказы, продажи, остатки FBO/FBS, реклама, документы, отзывы, вопросы, чаты, обычная финансовая детализация и прочие потоки;
- **Сервисный токен WB** — только «Сводки отчётов реализации» и «Сводки отчётов эквайринга».

Сервисный токен:

- нельзя назначить основным;
- нельзя использовать для обычных потоков;
- проверяется на backend как токен типа `acc=4` с категорией «Финансы»;
- сохраняется зашифрованно;
- никогда не возвращается в браузер;
- работает только вместе с `WB_CLIENT_SECRET` зарегистрированного сервиса.

Базовый токен нельзя случайно сохранить в сервисное поле, а сервисный — в основное.

## WB_CLIENT_SECRET

В карточке сервисного доступа показывается только безопасный статус:

- не настроен;
- настроен и действителен;
- истёк или имеет неверный формат.

Сам секрет хранится только в переменной окружения backend Render:

```text
WB_CLIENT_SECRET=<секрет зарегистрированного сервиса Wildberries>
```

ELISEI не отправляет значение секрета во frontend и не показывает его пользователю.

## Автоматические повторы

Для временных ответов WB `408`, `425`, `500`, `502`, `503`, `504` этап получает статус **«Автоповтор запланирован»**.

При этом сохраняются:

- текущий `taskId` сформированного отчёта;
- курсор и страница потока;
- метаданные текущего месяца архива FBS;
- ранее загруженные строки;
- причина и номер попытки;
- время следующего запуска.

Для `429` используется отдельный статус лимита WB и время из заголовка ограничения, когда оно доступно. Повторы выполняются с увеличивающейся задержкой и случайным разбросом, чтобы несколько кабинетов не повторяли запрос одновременно.

Старые состояния с ошибкой `504`, gateway timeout или network timeout при запуске backend автоматически переводятся в очередь повторов.

## Отдельная полоса архива FBS

«Архив заказов FBS» больше не участвует в общей тяжёлой очереди:

- имеет собственный фоновый worker;
- продолжает сохранённый месяц и курсор;
- не переписывает полный JSON подключения параллельно с другими потоками;
- не блокирует финансы, документы, рекламу и коммуникации;
- при общей ручной синхронизации ставится в фон отдельно.

Правила версии 5.6.3 сохранены: официальный endpoint архива, только `meta/details`, СГТ-склады только для чтения.

## Понятные статусы

Интерфейс различает:

- «Нужен сервисный токен»;
- «Нужен WB_CLIENT_SECRET»;
- «Нет права Финансы»;
- «Сервисный токен недействителен»;
- «Лимит WB — повтор автоматически»;
- «Временная ошибка WB — прогресс сохранён».

Для проблем сервисного доступа кнопка этапа открывает «Подключения», а не запускает заведомо невозможный запрос повторно.

## Версии

- Frontend: `5.6.4`
- Backend: `2.16.0`
- Потоков WB: `27`

## Установка

Скопируйте содержимое патча в корень репозитория **ELISEI 5.6.3** с заменой файлов.

1. Backend Render: **Manual Deploy → Clear build cache & deploy**.
2. Проверьте `/health`: версия backend должна быть `2.16.0`.
3. При наличии зарегистрированного сервиса добавьте в backend переменную `WB_CLIENT_SECRET`.
4. Frontend Render: **Clear build cache & deploy**.
5. Обновите кабинет через `Ctrl + F5`.
6. В «Подключениях» основной токен оставьте без изменений; сервисный добавьте в отдельную карточку.

Без `WB_CLIENT_SECRET` обычные потоки продолжают работать. Недоступными останутся только две официальные финансовые сводки, требующие сервисного доступа.
